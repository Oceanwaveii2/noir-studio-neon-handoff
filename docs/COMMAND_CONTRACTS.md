# Command contracts

## Shared local service and writer windows (RB-10–12)

`noir-service --timeline <existing timeline.sqlite> --books <library folder> --ticket <private ticket.json> [--port 8790]` starts the local HTTP service; `python -B -m prose_engine.service_daemon` is the checkout equivalent. Start with the restored copy and keep the ticket in a private directory outside source control. Noir uses 8790 by default; the older ProseCore port assignment (8780) remains in the workspace identity file. Start another app with `noir-workbench --service-ticket <same ticket.json> [--port 8791]` or `python -B tools/workbench.py --service-ticket <same ticket.json>`. The Workbench browser talks to its own local server; its Python client holds the ticket. It does not import the prose engine or open an episode or book file itself. Use `tools.noir_client.NoirClient` in a local Python app or implement the HTTP contract directly. A standalone Studio continues to work without the daemon.

| Route | Request and effect |
|---|---|
| `GET /v1/status` | Protocol, service instance, workspace identity, index loads/hits, available writer names and current window limits/usage. No provider is contacted. |
| `GET /v1/episodes` | Workspace identity and active episode IDs, titles, order, branches and saved heads. |
| `POST /v1/open` | `{"episode":"…","viewpoint":"…"}`: saved episode, exact-text beat map with source evidence, and existing notebook/protection state. Viewpoint is optional. |
| `POST /v1/scope` | `{"action":"rhythm-preview","request":{…}}` or `context`, `export`, `retrieve`, `validate`. Uses the normal scope with episode/revision/beat/range and project/universe/branch. Rhythm preview returns eligible cadence observations with receipts. No uncapped writer action is accepted here. |
| `POST /v1/command` | `{"action":"run.start","request":{…}}` or `director.open`, `director.preview`, `run.latest`, `run.status`, `run.resume`, `run.cancel`, `draft.open`, `draft.apply`, `notebook.undo`, `notebook.redo`, `timeline.history`, `graph.history`. Uses the existing episode commands, revision guards and history. |

Send `Authorization: Bearer` with the ticket's `token`. The daemon only binds to literal `127.0.0.1`, requires the matching Host, rejects requests with an Origin header and sends no CORS permissions. The bundled Python client disables redirects and proxies. The ticket is scoped to a database path, project, universe, port and writer window. For a restore to another path, create a separate, disabled ticket. Copy the ticket and its matching `.usage.jsonl.attempts.sqlite` journal together when recovering the **same** window; a missing journal is an error. The raw book indexes stay local to the service. Readers are reused only for the same verified release, policy, purpose, profile and input hashes. Changing those inputs opens a fresh verified reader. There is no automatic index download, rebuild or activation.

Writing starts disabled. For a bounded Codex window add `--allow-writer codex-session --max-attempts 1 --max-prompt-bytes 28000`, then use the existing source-bound run request (`episode`, `revision`, `branch`, `project`, `universe`, `source_sha256`, `anchor_token`, `notebook_revision`, `beats`, `provider`, `request_id`, `max_attempts`, `max_input_bytes`, `max_output_chars`; prompt and book choices are optional). The service checks the run's declared attempts and input bytes, then caps the actual calls across the entire ticket, including different episodes, writers and app calls. The same ticket cannot be reopened with a raised limit. A saved setup or preview cannot spend, and a locked passage uses zero writer calls. An uncertain send consumes its slot and must be reconciled locally; the service does not retry it or switch writers. The bound measures requests dispatched by Noir and UTF-8 prompt bytes; it does not estimate tokens, provider billing, or hidden retries performed by external software. Restarting and reading progress cannot start a run. An eligible queued or interrupted run can be resumed explicitly under the original saved request and ceiling. The connected Workbench reads progress and drafts; the service client can submit a request explicitly.

Codex and Gemini use the existing isolated Narrative Composer bridges. For an installed copy, `NOIR_COMPOSER_BRIDGE_CONFIG` points to that local configuration JSON (it contains `composer_root`); auth remains in the actual host session. Set the host environment variable `NOIR_SESSION_REGISTRY` to an explicit local JSON file to add DeepSeek, Claude, Grok, or another compatible session:

```json
{
  "schema_version": 1,
  "writers": {
    "claude-session": {"label": "Claude", "argv": ["C:/NoirAdapters/claude-writer.exe"], "timeout_seconds": 90}
  }
}
```

Use an installed wrapper that takes one UTF-8 prompt on standard input, sends one request to the selected host and returns just the candidate text on standard output. Configured commands run with fixed arguments in a disposable working folder. Request payloads cannot supply paths or arguments. `deepseek-session`, `grok-session` and other names ending in `-session` follow the same shape. New host choices appear in scoped Studio/CLI sessions; allow them individually on the service. Existing standalone editorial and legacy generation paths do not share a service ticket or its writer ceiling.

`python -B tools/u8_package.py --out <new local directory>` builds the application wheel: core, daemon, connected Workbench, Studio and assets. `noir-studio --timeline <restored timeline.sqlite> --books-dir <library folder> [--images-dir <existing portrait folder>]` opens an installed Studio. Supply story files, node media, model weights and books separately; the wheel contains no manuscript, databases, book text or credentials. Install the optional `corpus` dependencies for PDF text extraction. The service and app packages do not install optional models, add OCR or replace the legacy standalone editor.

Each command states inputs, outputs, state effects, failure modes, and recovery. Behavior for
the same operation must not drift between CLI, library and future UI.

The [project behavior registry](../.app-steward/behavior/commands.json) records current bindings and
bindings for the story graph, editorial routes, Studio and verification. See
[reviewed edits](REVIEWED_EDITS.md) for the shared CLI, Studio and Workbench workflow.

## Invariants

- `condition --apply` never mutates the input file or generates text.
- Every rejected candidate carries a reason string in `proposals.json`.
- A rewrite must pass: facts, quotes, length ratio 0.4–2.2, no new warning types, overlap ≤ 0.82.
- Provider failures are recorded per paragraph and never abort the pass.
- No command sends document text to a network provider unless the provider was named explicitly.


### Session attempts and scoped proposal safety (NM-01 and NM-02)

Codex, Gemini and DeepSeek session adapters reserve each dispatch in the SQLite attempt journal before calling the handler. A reservation counts against the job even after a timeout or restart. Unresolved attempts block the same provider and recovery scope. Studio and the scoped CLI share a recovery scope for the same timeline file and episode. Standalone integrations can supply a stable job ID when resuming a job. The legacy JSONL file remains an optional success receipt.

The session adapter commits the original response text, its UTF-8 SHA-256 and the attempt outcome together before returning to the run. The journal also records the dispatched prompt SHA-256. Attempt listings return metadata and digests. Keep the journal private with the matching workspace backup. Attempts created before response storage retain their original states and budget charges.

Use `python -m prose_engine session-attempts` to inspect the default session journal (use `--ledger eval/session_usage.jsonl` for the legacy DeepSeek location). Reconciliation requires `--attempt ID --state STATE --checked`. Only classify an abandoned started request as remote unknown after confirming the original worker is stopped. A cancel request does not send a remote cancel signal; mark cancelled only after confirming remote cancellation. Reconciliation never refunds a consumed attempt.

Without a notebook, scoped proposals preserve recognized dialogue; an initialized notebook instead uses the author’s protection settings. Explicit `protected_ranges` (CLI `--protected-ranges`) are always exact, expressed as absolute Unicode code-point offsets on the selected revision. The engine checks exact substrings in order, including whitespace and punctuation, and blocks omitted or altered protected text. When notebook protection covers the entire selected passage at 100%, the entire output must equal the input; additions at its boundaries are also rejected. Studio and CLI recheck revision and scope after generation; a proposal includes its revision and selection. Exact matching and typed event/form checks cannot prove semantic correctness of generated prose, detect all invented facts or rule out paraphrased future information. Author review remains necessary. Standalone, non-timeline prose routes do not gain these timeline checks.

### Reference eligibility and provenance (NM-03 / NM-04)

The covered retrieval paths use the shared author-controlled purpose policy and existing influence preferences before ranking. Missing configuration leaves sources unclassified; it does not change their influence settings. New chunk IDs include source revision and ordinal; existing index rows use an index fingerprint and original position. See [reference policy](REFERENCE_POLICY.md) for configuration, coverage and limitations.

`books/library_quality.json` is an independent source-quality exclusion list, not a rewrite of author permissions. Corpus loading and loaded source policies exclude these records before scoring, including retained legacy indexes. Invalid quality configuration fails closed; modifying it invalidates scoped library/draft bindings. Removed-from-use originals remain available for recovery and historical provenance. Supplied replacements get distinct edition IDs and hash-linked source copies; identical attachments are recorded once, never silently substituted into an old source ID. Image-rich books with corrupt embedded OCR remain excluded until a usable extraction is reviewed.

### LUAR scoring, source controls and legacy receipt mapping (NM-05 / NM-03 / NM-04)

Conditioning and Workbench use the shared policy-aware retrieval setup. Requested but unavailable retrieval is visible and stops the rewrite instead of silently falling back. The conditioner checks the eligible reference index before provider dispatch, uses the same selected LUAR encoder/index to score the original and candidate, and retains a rejected candidate if post-response scoring fails. LUAR has no acceptance threshold until calibrated; existing topic and style thresholds remain separate. Prompt permission does not grant reference export. Workbench allows per-source policy edits without modifying influence preferences. Legacy rank receipts map only when their saved text and source uniquely identify a location, with an anchor required for duplicates. Scoped Studio generation can also use eligible book-index references when requested and available; see [NR-04](NR-04_SCOPED_BOOKS.md). See [reference policy](REFERENCE_POLICY.md).

### Offline LUAR calibration (NM-05)

The score command computes bounded local pair scores against permitted reference sources, with hashes for the index, source policy and influence settings. The evaluator chooses a candidate on document-disjoint development data and reports held-out false-rejection and detection counts. Synthetic labels are explicitly synthetic; author-reviewed data requires declared reviewer and decision evidence. Outputs omit passage text, never overwrite existing files and never change the live threshold. See [LUAR calibration](LUAR_CALIBRATION.md).

### Index compatibility and versioned LUAR preprocessing (NM-06)

Reference index audit writes a new text-free manifest and never modifies source indexes. New LUAR indexes use token-mask-v2, pin a cached model revision, record source/chunk hashes and runtime, and reject mismatched encoders or runtimes; save_new refuses an existing path. Existing LUAR indexes remain on the legacy path with explicit unverified status. Style index loaders resolve the style model relative to the selected index and check fingerprints when available. No index is promoted automatically. See [NM-06 compatibility](NM06_INDEX_COMPATIBILITY.md).

### Versioned library replacement (NOIR-LIB-001)

`tools/library_rebuild.py configure --expected-revision HASH --remote` is an explicit one-time setup for currently usable unconfigured sources. It preserves every existing policy entry and influence-off choice, excludes blank/quality-held sources, and does not grant export. Omitting `--remote` grants no new transfer permission. Configuration uses a cooperating publication lock and expected-byte revision; it is never a GET side effect.

`build --out NEW_DIRECTORY --batch-size 4 --max-cuda-mb 2048` builds separate offline topic/LUAR/style candidates. It pins cached model bytes/revisions, runtime, encoder/chunker code, source catalog and quality review; validates saved dimensions, finite values, source coverage and per-source exact-query probes. Insufficient GPU headroom or another failure leaves the active pointer unchanged; partial candidate outputs are retained and not automatically retried or published. Do not edit encoder/chunker/model/source files during a build.

`activate --candidate DIRECTORY --name VERSION` rechecks saved bytes, source coverage/revisions, probes and encoder bindings; copies to a new immutable-by-contract `books/index_releases/VERSION` directory and atomically selects it through `books/library_active.json`. It refuses an existing destination or stale pointer/catalog, and never overwrites the three legacy canonical indexes. A bad active pointer fails closed rather than falling back. Shared retrieval, CLI reference inspection/variant ranking/generation, the local evaluator centroid and Workbench source snapshots select this release; explicit low-level builders continue reading their supplied physical staging directory. Recovery is copy-first from retained receipts, source editions and checkpoints, not an automatic index swap or deletion.

Studio `/api/book-status` reports all three backends, usable/eligible counts, quality exclusions and blank sources without constructing an encoder or generating text. Legacy compatibility is `incomplete`, not verified readiness. Scoped prompts identify the bounded excerpt sources and carry descriptive cadence observations; text-free receipts bind source/title/author, exact excerpt hash/length, catalog, quality, policy, influence, release and encoder. Consecutive-beat aggregate drafts retain each child's cadence observation and provenance. This is functional evidence, not literary acceptance, a real primary-session test, or a calibrated LUAR quality threshold.


### Notebook, masks and drafts (NM-07–09)

Episode-scoped notebook records and draft variants use optimistic revision checks. Protection offsets are Unicode code points; exact hard locks cannot be softened by a lower dial. Mutations and undo retain prior revisions. Generating is explicit, and incomplete attempts must remain distinguishable from completed drafts. UI and CLI integration will be recorded with its verified coverage.

Studio v2’s compact **Workspace** picker uses the same view handler as the desktop tabs. At narrow widths **Episodes** and **Inspector** open one drawer at a time. Escape dismisses an open drawer and focuses its button. The notebook wraps to the available stage width. From a text selection, Tab enters the protection choices and Escape returns focus to the selected text. A saved single-passage mask restores the selection using its existing notebook offsets. Viewport sizing and drawer changes leave manuscript and mask data intact.


### Universe world laws

The timeline store keeps revisioned universe laws. Studio can read, edit, activate and undo them; scoped generation, validation and export consume the current law revision. Source-linked structured constraints and explicit claims support relationship-aware checks, bounded branches and timeline intervals; uncertain beliefs and source quotations are not treated as established facts. Narrow Haley parentage and author-configured literal phrase checks remain diagnostics for prose. These checks cannot prove general semantic compliance or cover paraphrases. Existing unrelated/non-timeline routes are not yet connected. Laws never start a provider call. See [NR-02 world laws](NR-02_WORLD_LAWS.md) for the schema and current UI and extraction limitations.


### Project and universe context (NR-01)

A scoped operation binds to a persistent project and universe, episode, branch, beat, viewpoint, source and graph revisions and world-law revision. Existing unbound databases require an explicit copy-first migration; old law records and files are preserved. Unscoped legacy routes do not inherit a universe implicitly. See [NR-01 universe scope](NR-01_UNIVERSE_SCOPE.md) for migration, tested coverage and remaining limits.

Studio timeline actions, Workbench timeline mode and the scoped CLI use a common operation service and the same packet compiler, validators, provider recheck and draft application rules. Scoped generation may explicitly select a policy-eligible topic, LUAR or style index, or select no books. Source and influence settings are filtered before ranking, story-tagged records are excluded, and the selected policy/index is rechecked around dispatch. Text-free receipts accompany drafts. Missing permissions never silently enable books or fall back to an unfiltered index. See [NR-04 scoped books](NR-04_SCOPED_BOOKS.md) for configuration and limitations.

Unlinked empty ports are explicitly incomplete. Both `CharacterProfileStore` and `FormGraphStore` `node_data` (`character_store_token`) edits are revision checked and invalidate stale drafts; uploaded attachment blobs remain outside generation. ### Beat rhythm (NR-06)

An episode beat may carry revisioned pace, tension, pause, comedy, cadence, transition and author direction, optionally bound to a matching graph node. Studio derives a read-only, revision-bound map of provisional passage beats from the saved episode and groups them under explicit scene headings. These are paragraph boundaries, not automatically proven narrative beats or timeline anchors. A selected scene or up to eight consecutive passage beats can be sent to the Prose Engine; each passage has a separate scoped call, and successful results are assembled into a recoverable composite draft. Current reviewed timing supplies each passage's cutoff; unassigned passages use beat 0, while stale/ambiguous assertions block writing until reviewed. Eligible book excerpts can contribute bounded descriptive cadence observations, not quality scores. Saved prose changes produce a fresh projection when the map is reopened. See [NR-06 beat rhythm](NR-06_BEAT_RHYTHM.md) and [the automatic beat map plan](NR-09J_AUTOMATIC_BEAT_MAP.md).

**NOIR-RHY-001:** scoped generation now compiles these controls into concrete advisory rhythm techniques. Same-scene groups receive distinct ordinal entry/development/exit suggestions, never later passage text or inferred story timing. Explicit author directions/controls override automatic suggestions and reference cadence; exact locks, facts and laws remain authoritative. Fully 100%-protected selections suspend all rhythm suggestions. New draft JSON retains the plan and descriptive before/after cadence, including blocked/stale returned candidates; group drafts retain each child's plan/evidence. No rhythm score, automatic plot outcome or additional generation call is introduced.

`execute_scoped(..., 'rhythm-preview', request)` and `preview_group(...)` use the same compiler and reference eligibility as generation without constructing a writing provider or recording a draft. Studio exposes **Preview selection rhythm** and **Preview selected-beat rhythm**; HTTP uses `/api/scoped` action `rhythm-preview` or `/api/beat-group` action `preview`. Eligible references may load the existing local retrieval encoder; context/export remain encoder-free. Preview is optional, not a repeated approval gate. Supplying a returned `rhythm_plan_id` to generation rejects plan drift before dispatch; group generation always freezes its own preflight plan and stops further calls on scope/rhythm/library drift, retaining completed children. These are functionally verified craft instructions, not proof of semantic pacing or a real primary-session run. See [rhythm integration](NOIR_RHYTHM_INTEGRATION.md).

### Reviewed passage timing (NOIR-BEAT-001)

`BeatAnchorStore.open(episode, revision, viewpoint=...)` returns the read-only map, eligible same-episode event choices and viewpoint-specific revision history. `change(action, request)` accepts `bind`, `bind_scene`, `unbind`, `undo` or `redo`; writes require `episode`, `revision`, `project`, `universe`, `branch`, `source_sha256`, `passage`, `expected_token`, `reviewer`, optional `viewpoint`, and an `event` for binding (or `scene` for `bind_scene`). `/api/beat-anchors` exposes this same domain path with an explicit `action`, JSON size bounds and same-origin checks. Binding asserts the **whole exact passage** can use context through the chosen approved permitted event; it does not create canon or prove semantic timing. Graph dialogue-match numbers are never cutoffs. Undo and Redo append the prior or undone assertion only when its exact source and evidence still match.

The additive `passage_anchor_revisions` table is created only by a valid explicit timing write. Rows are append-only by service contract; reads never migrate the store. Bindings retain stable IDs, scope/source/graph fingerprints, reviewer, event evidence and viewpoint. Unique unchanged paragraph text can identify a prior ID after edits, but the cutoff stays stale/zero until explicitly rebound. Duplicates are ambiguous; edited text without a unique exact match is a new unassigned passage. Source revision or evidence drift never silently advances context. Undo appends the prior assertion only when its source/evidence still match.

Mapped requests carry `passage_anchor`; groups always compile and bind each child's own timing, laws, history, character forms and rhythm. A displayed `anchor_token` can be supplied with a group to reject intervening assignment edits. Pre-dispatch and post-return checks retain stale candidates. Composite drafts retain child IDs, individual writing contexts, source/candidate offsets and exact separators. Applying reconstructs and validates **every child at its own cutoff**, never at the group's latest beat, then checks all anchor and rhythm guards in the same SQLite edit transaction. Whole-group apply and undo preserve existing protections. Partial composite apply is deliberately rejected; use an individual child draft instead. Existing pre-feature drafts remain recoverable under their original single scope; existing explicit unassigned timeline operations are not automatic semantic mapping. See [beat anchors](NOIR_BEAT_ANCHORS.md).

For the exact imported Hot Scoomp manuscript, `story_graph.source_timing` ties three passage windows to actual source lines. Its receipt requires the original edition, exact saved text and the existing approved awakening event. The event takes effect at cut 2, after the written reveal; extra time in a request cannot move it into the lead-in, flashback or unverified passages. The map labels intact ranges **Verified from script**. The reading cutoff and the selected character's knowledge are separate: narrator context gets the prior reader reveal, and Haley, Holly and Francine get witnessed history. Prompt, structured rewrite request, retrieval, validation and exports use the same filtered projection. Later eligible branches inherit it; earlier forks and unverified old snapshots do not. If the source changes or approval is withdrawn, the imported event is withheld rather than treated as beat zero. No event row is rewritten. See the [real-script verification](NOIR_RB02_RB03_REVIEW.md).

For the AFM Spring Break episode, an exact match to the existing MO2 hybrid manuscript or production archive enables unique, normalized dialogue matches to the existing 20-beat MO2 graph. An exact match to the separate legacy prose-engine screenplay instead enables the corresponding 10-beat graph. The automatic dialogue projection reports graph IDs and fingerprints as evidence only. Separately, verified windows in the saved Spring Break r3 manuscript match that saved MO2 graph's beats 13 and 14 at the nanite transfer and Nurse Franny's arrival. They require both manuscript and graph fingerprints and use those existing graph cutoffs. Unverified passages and other editions do not inherit the reviewed mapping.

Studio's narrator/character add actions append a typed notebook block through the same revision-checked notebook store. A character block records the supplied name; it does not claim a connected character node or personality model. Adding a block may save pending episode edits first. The operation preserves existing source anchors and masks, records a notebook revision, and can be undone through notebook history.

Writing blocks use the text field's native click and text-selection behavior, including keyboard select-all. The separate Select block button has been removed; the highlighter continues to operate on the selected text.

The Racing composer uses a black block header with orange accents and readable notebook-style labels. The document-protection sidebar and the smaller selection popup use the existing revision-checked notebook settings and Racing dial animations; changing a weight does not start generation. When an imported block has no saved identity, clear speaker cues or narration can provide a display-only inferred label. The stored source, block identity and character graph are not changed; unassigned dialogue remains Dialogue. Inference is limited and is not a character personality model.

An explicitly placed `cue_prefix` shows the exact saved cue in the Studio v2 block header and exposes the remaining dialogue in its editor. It does not insert a newline. Save reconstructs the original block order and text separators and retains the stored graph; selection and split positions include the cue's original length. If the text no longer starts with the marked cue, the editor displays the full text. The legacy editor still displays the raw block.

The intended writing loop is set out in the [Mule and DLSS workflow report](noir-visual-plan-2026-11-09/00_NOIR_MULE_MASKED_STORY_WORKFLOW_REPORT.md). The saved manuscript and scoped story rules are the input; exact locks remain unchanged and lower protection settings give the writer session room to revise. A writing run saves a variant under its episode, where applying an eligible draft is an ordinary document edit with Undo and Redo. There is no reviewer step for that edit. **Cook** in Compose prepares the notebook; **Cook to draft** in Beat Map runs the selected passages through the writer. **Generate Selection** in Prose Engine handles an explicit saved text selection.

### Director, writing runs and shared episode commands (RB-04–06)

**Generation receipts.** Use `run.selection` for the author's Generate Selection action. It accepts the scoped selection and stable `request_id`. A fully protected range returns `PRESERVED` and its saved scope without a draft. A fully protected Beat Map run records `PRESERVED` with zero planned attempts and no composite draft. Legacy scoped commands still expose preserved text under their existing contract. For a generated proposal, `writer_receipt` records the request ID, prompt and response SHA-256, and the attempt ID when the provider supplies one. A Beat Map result includes `generation_receipt` only when its saved composite has recorded writer contributions. Preserved child passages may sit alongside those contributions. Supplied bridge text is saved as `origin: imported`. Older drafts lacking provenance retain an unknown origin.

**Graph Cook.** `graph.cook` takes `episode`, saved `revision`, `mode` (`selected` or `downstream`), and `target` (required in Selected mode). It checks the saved graph structure and dependency order. Downstream checks the target and dependents with their prerequisites, or the whole graph when no target is selected. The receipt identifies the episode, graph revision, graph SHA-256, dependency order and checked nodes. Locked and bypassed nodes retain their state. An identical request reuses the persisted result. Unsaved edits, stale responses and failed requests cannot mark nodes clean in Studio. This command is structural evaluation. Beat Map and Generate Selection provide writing.
